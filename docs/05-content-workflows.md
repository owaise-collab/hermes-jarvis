# Educational content workflows

## One lesson, three adaptations

Use a single checked lesson record as the input to the three format workflows. Record the learning objective, age group, language, exact reference material, original story details and review status. Include source URLs or bibliographic identifiers, and mark whether Arabic/translation and interpretation have been reviewed. The application does not verify these automatically.

Example brief:

```text
Audience: ages 6–8, English.
Goal: identify one practical way to include someone who feels left out.
Setting: an original fictional playground scene.
Religious evidence: use only the selected source note. If it does not
support a claim, mark that claim NEEDS SOURCE REVIEW rather than inventing evidence.
Output: a short lesson, a question, and one family activity.
```

For an initial workflow test without religious review, use a clearly labeled fictional kindness activity and no religious attribution. That tests the production mechanics without falsely certifying a teaching.

## Carousel

Ask for eight slides, one concept per slide, short body copy and a visual brief. Review narrative continuity and references. The output is a script, not rendered slide images. A future renderer can read the approved script into a consistent 1080×1350 template; do not imply that this panel already creates illustrated carousels.

## Children's video

Ask for a 60-second storyboard with scene action, narration, screen text, asset needs and a response pause. Keep character/setting descriptions stable for later asset production. This kit does not render animation, generate character images or synthesize final Arabic narration. Locally installed image/video tools may be added later; hosted AI image generation would be an explicit external workflow.

## Printable

Ask for a child activity and separate parent guidance/source page. Open the output and use Print / PDF. The current exporter prints the draft text with readable line wrapping; it is not a polished workbook-layout engine, fillable PDF system or Arabic typesetting certification. Review pagination, right-to-left text and writing space before sharing.

## Human checkpoints

Check religious evidence and its interpretation; distinguish Quran/hadith from original examples; review age suitability, Arabic spelling and pronunciation; and verify the actual exported artifact. A small local model can draft structure and adaptations, but should not be the authority deciding whether a quotation or ruling is authentic.

## Practical automation boundary

Automated now: note capture/search, explicit source selection, draft templates, saving provenance, local dictation, English speech, no-model inventory and browser print layout. Not automated: religious approval, source retrieval/certification, illustration, video rendering, social publishing, DMs or unattended execution. These boundaries are visible in the UI and keep the production record honest.
