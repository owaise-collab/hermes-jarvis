# Privacy and security boundaries

## What stays on this machine

The panel's HTTP listener binds only to literal IPv4 loopback. Model requests use the loopback llama.cpp endpoint with no proxies, redirects, API-key discovery or remote fallback. Browser assets are bundled locally. Speech adapters load existing model caches; Whisper explicitly sets `local_files_only=True` and the server sets Hugging Face/Transformers offline flags. Piper loads an explicit local ONNX file.

Dictation audio and generated speech are kept in memory by the panel. Submitted requests, selected note paths and generated answers are saved as plaintext Markdown outputs. Unsubmitted dictated text remains in the browser input; it is not saved by the panel. OS audio infrastructure, swap, browser behavior and the speech libraries are outside a claim of forensic zero retention.

## What this does not guarantee

- Localhost is not an encrypted vault. Anyone with access to your OS account/files can read saved material.
- Other local programs can read the panel's initial HTML and obtain its session token. The token protects browser-origin requests, not a hostile local machine.
- Full Hermes agent tools, plugins and terminal commands can access the network. This project does not alter firewall rules or sandbox the whole agent process.
- Existing Hermes configuration may contain other integrations. The installer changes the listed text/speech routes; it does not certify every plugin or every auxiliary modality as offline.
- Model/voice installation and package repair need downloads. GitHub publishing intentionally transmits reviewed source files and documentation.
- Obsidian sync and other user-installed plugins have their own network behavior. This kit does not install or configure them.

## Web-facing protections

Every API read/write requires an unpredictable per-process token. POST requests must have the same origin when an Origin header is present. The Host header must match `127.0.0.1:PORT`; this rejects DNS rebinding through arbitrary hostnames. There is no CORS opt-in. CSP restricts page resources and fetches to self; frame embedding, base URL replacement, camera and geolocation are disallowed. Dynamic user/model text uses `textContent`, not HTML parsing. Note paths are resolved and confined to the vault's three areas. File names are generated by the application rather than trusted from a model.

These controls are not a multi-user authentication service. Do not expose the port to a LAN, tunnel or reverse proxy. Multi-user sharing would require a separate design for authentication, authorization, data separation, request limits and process isolation.

## Publication

Only this source checkout is staged. The Hermes home itself is not a Git repository. Do not initialize Git at the Hermes home or upload its full contents.

Excluded state includes `.env`, `auth.json`, `config.yaml`, SOUL, backup manifests, sessions, memories, audio, model weights and generated vault content. Repository checks reject common credential patterns, personal absolute paths and accidental binaries. Automated scans reduce mistakes; they cannot prove that arbitrary prose contains no private information. Review the staged file list and diff as well.

The screenshot for documentation must show only the empty/synthetic panel, never private notes or credentials. A private GitHub repository is the conservative default for this setup; public release is a separate visibility decision.
